# Спецификация 001: Библиотека автомобилей (MVP)

> SDD, фаза 3 (`/feature`) и фаза 4 (`/clarify`). Спека описывает поведение с точки зрения пользователя, про технологии здесь ничего нет.

## Пользовательские истории

### US-1. Список и поиск (P1)
**Как** посетитель, **я хочу** на главной странице видеть все автомобили и искать нужный по названию, **чтобы** быстро попасть на его страницу.

Критерии приёмки:
- AC-1.1. На главной показаны все автомобили из базы: фото, марка, модель, поколение, тип кузова, годы выпуска, мощность.
- AC-1.2. Поле поиска фильтрует список **по мере ввода** без перезагрузки страницы.
- AC-1.3. Поиск не зависит от регистра и ищет подстроку в марке, модели и поколении («камри», «Camry», «xv70» и т. п.). Поддерживаются русские названия марок и моделей (см. поле `aliases` в модели данных).
- AC-1.4. Если ничего не найдено, показывается пустое состояние «Ничего не найдено» с кнопкой сброса поиска.
- AC-1.5. Клик по карточке открывает страницу автомобиля `/cars/<slug>`.
- AC-1.6. Пока данные грузятся, показывается скелетон. Если сервер недоступен, показывается сообщение об ошибке с кнопкой «Повторить».

### US-2. Страница автомобиля (P1)
**Как** посетитель, **я хочу** видеть всю информацию о машине на одной странице.

Критерии приёмки:
- AC-2.1. Галерея фотографий: несколько фото с переключением и подписью «автор / лицензия / источник».
- AC-2.2. Основная информация: марка, модель, поколение, годы выпуска, класс, тип кузова, краткое описание.
- AC-2.3. Технические характеристики сгруппированы: «Двигатель и трансмиссия», «Динамика и расход», «Размеры и масса».
- AC-2.4. История марки: страна, год основания, текст истории.
- AC-2.5. Кнопки «Купить на auto.ru» и «Купить на Авито» открывают поиск этой модели на агрегаторе в новой вкладке.
- AC-2.6. По несуществующему `slug` показывается страница «Автомобиль не найден» со ссылкой на главную.
- AC-2.7. Есть навигация назад, к списку (хлебные крошки).

### US-3. Расширяемость каталога (P2)
**Как** владелец проекта, **я хочу** добавлять новые машины без изменения кода.

Критерии приёмки:
- AC-3.1. Новая машина добавляется новой SQL-миграцией и появляется на сайте после перезапуска бэкенда.
- AC-3.2. В README описано, как добавить машину.

## Функциональные требования

- FR-1. Система отдаёт список всех автомобилей в кратком виде.
- FR-2. Система отдаёт полную информацию об автомобиле по его человекочитаемому идентификатору (`slug`).
- FR-3. Данные хранятся в базе данных, фронтенд их не хардкодит.
- FR-4. Стартовый набор: 10 автомобилей 10 разных марок, популярных на рынке РФ.

## Нефункциональные требования

- NFR-1. Локальный запуск на macOS: бэкенд и фронтенд стартуют каждый одной командой.
- NFR-2. Ответ API на локальной машине приходит быстрее чем за 100 мс.
- NFR-3. Интерфейс на русском языке и корректно выглядит на мобильной ширине (от 375 px).
