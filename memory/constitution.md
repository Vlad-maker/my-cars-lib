# Конституция проекта

> SDD, фаза 2 (`/generate-constitution`). Это неизменные правила: любой спек, план и код проверяются на соответствие им. Меняются только осознанно, с записью в `event-stream.md`.

## Статья I. Спецификация первична

1. Код пишется только по задаче из `specs/<NNN-feature>/tasks.md`.
2. Если реализация расходится со спекой, сначала правим спеку и только потом код (Drift Rule из `go-standards`).
3. Неясность в спеке помечается как `[NEEDS CLARIFICATION: ...]`. Пока такие пометки не разрешены, реализацию не начинаем.

## Статья II. Стек (фиксирован)

| Слой | Технология |
|---|---|
| Фронтенд | React 19 + TypeScript + Vite |
| UI-компоненты | Astryx (`@astryxdesign/core`) + тема `theme-neutral`, свою дизайн-систему не придумываем |
| Состояние | Zustand |
| Роутинг | React Router |
| Бэкенд | Go, HTTP-фреймворк Gin (по `go-standards/references/libraries.md`) |
| База данных | SQLite (файл), драйвер `modernc.org/sqlite` без CGO |
| Миграции | `golang-migrate` (SQL-файлы, встроены в бинарник через `embed`) |
| Тесты Go | `testing` + `testify` |

## Статья III. Правила бэкенда (из плагина go-standards)

1. **Плоская структура** `internal/<domain>`, потому что домен тонкий (чтение каталога), транспорт один, разработчик один. Четыре слоя Clean Architecture не вводим, пока что-то конкретное этого не потребует.
2. Зависимости направлены внутрь: `httpapi` → `car`, но не наоборот. Пакет `car` не импортирует `net/http` и `gin`.
3. Интерфейсы объявляет **потребитель**.
4. Ошибки всегда оборачиваются с контекстом: `fmt.Errorf("get car %s: %w", slug, err)`. Доменные ошибки (`ErrNotFound`) маппятся в HTTP-статус только в хендлере.
5. Логи пишутся через `log/slog`, конфигурация читается из переменных окружения.
6. Ответы API: `{"data": ...}` при успехе, `{"error": {"code", "message"}}` при ошибке.
7. Перед завершением задачи проходят `go build ./...`, `go vet ./...` и `go test ./...`, а также `golangci-lint run`, если он установлен.

## Статья IV. Правила фронтенда

1. UI собирается из компонентов Astryx. Свой CSS пишем только для раскладки, которой нет в Astryx.
2. Все запросы к API идут через один модуль `src/api/`, компоненты не вызывают `fetch` напрямую.
3. Глобальное состояние (список машин, строка поиска) хранится в Zustand-сторе, локальное лежит в `useState`.
4. TypeScript-типы ответов API повторяют контракт из `specs/.../contracts/api.md`.

## Статья V. Данные

1. Любое изменение схемы или данных оформляется **новой** миграцией. Уже применённые миграции не редактируем.
2. У фотографий хранятся автор и лицензия (Wikimedia Commons), и на сайте они показываются.
3. Характеристики даются для базовой или самой популярной версии и помечаются как справочные.

## Статья VI. Git

1. Коммит делается после каждой завершённой задачи или фазы, в формате Conventional Commits (`feat:`, `docs:`, `fix:`).
2. В репозиторий не попадают секреты, `node_modules`, файлы БД и сборки.
